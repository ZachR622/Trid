API reference

Everything the library exports, module by module. Points are plain { x, y, z } objects (or { x, y } on screen); no function changes its inputs unless it says so.

Math

Pipeline — math/transform.js

localToWorld(v, inst) → point

Moves a mesh vertex into world space using an object's transform: scale, then rotate (X → Y → Z), then translate by pos. inst needs pos, rot and scale.

worldToCamera(p, camera) → point

Moves a world point into camera space: subtracts the camera position, then undoes its yaw and pitch. In camera space the camera sits at the origin looking down +Z, so z is the distance in front of it.

cameraToScreen(p, camera, w, h) → { x, y }

Projects a camera-space point to canvas pixels, using camera.fov and the aspect ratio w / h. p.z must be > 0 — clip segments with clipNear first if they can cross behind the camera.

worldToScreen(p, camera, w, h) → { x, y }

worldToCamera followed by cameraToScreen. Handy for placing labels on top of 3D points.

clipNear(a, b, near) → [a, b] | null

Clips a camera-space segment against the plane z = near. Returns the segment unchanged if both ends are in front, null if both are behind, or a shortened segment with the hidden end moved onto the plane.

Camera directions

cameraForward(camera) → point cameraRight(camera) → point cameraUp(camera) → point

Unit vectors in world space for where the camera looks, the screen's right side and the screen's top side. Use them to move things relative to the view.

Constants

DEFAULT_FOVMath.PI / 2 — 90° vertical field of view
DEFAULT_NEAR0.01 — near plane distance

Basic transforms

scale(p, sx, sy, sz) → point translate(p, dx, dy, dz) → point rotateX(p, angle) → point // pitch, YZ plane rotateY(p, angle) → point // yaw, XZ plane rotateZ(p, angle) → point // roll, XY plane rotateXYZ(p, { x, y, z }) → point // X, then Y, then Z

Each returns a new point. Angles are in radians. Rotation order matters: rotateXYZ always applies X first, then Y, then Z.

Projection — math/projection.js

project(p, fov = Math.PI / 2, aspect = 1) → { x, y }

Perspective projection of a camera-space point to normalized coordinates (−1 to +1). X is divided by aspect so shapes don't stretch on wide canvases. p.z must be > 0.

screen(p, w, h) → { x, y }

Converts normalized coordinates to canvas pixels. Y is flipped: +1 is the top of the canvas.

Rendering

Drawing — render/draw.js

clear(ctx, w, h, color)

Fills the whole canvas with color.

point(ctx, p, color, size = 20)

Draws a filled square centered on screen point p. Useful for debugging vertices.

line(ctx, p1, p2, color, width = 4)

Draws one line between two screen points.

drawWireframe(ctx, points2, edges, color, width = 4)

Connects already-projected screen points using index edges (2 indices = segment, 3+ = closed loop). Everything is stroked as one path. No clipping is done.

drawInstance(ctx, inst, camera, w, h, color, lineWidth = 3)

The main drawing call: transforms an object's mesh, clips every edge against the camera's near plane, projects it and strokes it as one path. This is what Scene.render uses for each object.

Frame loop — render/loop.js

loop(update, { maxDt = 0.1 } = {}) → stop()

Calls update(dt, time) every animation frame with requestAnimationFrame. dt is the seconds since the last frame (0 on the first, capped at maxDt) and time is the seconds since the loop started. Call the returned function to stop.

Using the pipeline without Scene

Scene is a thin layer over these functions. You can drive them yourself:

import { clear, drawInstance, point } from "./trid/render/draw.js";
import { loop } from "./trid/render/loop.js";
import { makeShape } from "./trid/render/shapes.js";
import { worldToScreen } from "./trid/math/transform.js";

const canvas = document.getElementById("demo-raw");
const ctx = canvas.getContext("2d");
const { width: w, height: h } = canvas;

const camera = { z: -1.5, fov: Math.PI / 3 };
const box = {
  mesh: makeShape("box", { w: 0.8, h: 0.4, d: 0.4 }),
  pos: { x: 0, y: 0, z: 0 },
  rot: { x: 0.4, y: 0, z: 0 },
  scale: { x: 1, y: 1, z: 1 },
};

loop((dt, time) => {
  box.rot.y = time * 0.8;
  clear(ctx, w, h, "#141414");
  drawInstance(ctx, box, camera, w, h, "#e5c07b", 2);

  // A dot circling the box, projected by hand
  const p = { x: Math.cos(time) * 0.7, y: 0, z: Math.sin(time) * 0.7 };
  point(ctx, worldToScreen(p, camera, w, h), "#E9806E", 8);
});

Helpers — tools/helpers.js

pick

pick(scene, x, y, { filter, padding = 4 } = {}) → object | null

Returns the object under canvas pixel (x, y). An object is hit when the point is inside its screen-space bounding box, grown by padding pixels. If several are hit, the one whose center is closest to the camera wins. filter(obj) can exclude objects.

Bounding boxes are approximate: clicking the empty corner around a sphere still picks it.

screenBounds

screenBounds(scene, obj) → { minX, minY, maxX, maxY } | null

An object's bounding box on screen, in canvas pixels. Only vertices in front of the near plane count; returns null if the whole object is behind the camera.

worldPerPixel

worldPerPixel(scene, depth) → number

How many world units one canvas pixel covers at depth units in front of the camera. Multiply pointer dx/dy by it to make something follow the cursor exactly.

ToolManager — tools/manager.js

Each scene creates one as scene.tools. It keeps the tool list and turns canvas pointer events into tool events. Canvas listeners are only added while at least one tool is in the list. You normally go through scene.use / scene.unuse instead.

MemberMeaning
new ToolManager(scene)Creates a manager for a scene's canvas
add(tool)Adds a tool and calls its attach. Adding the same tool twice does nothing.
remove(tool)Removes a tool (ending its drag if it holds one) and calls its detach
clear()Removes every tool
update(dt)Calls every tool's update
draw(ctx)Calls every tool's draw
listThe tools, in the order they were added
